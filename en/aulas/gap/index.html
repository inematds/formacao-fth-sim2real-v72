Lesson 1 · 16 min

Where the simulator lies about a humanoid

A policy that walks in the simulator and falls on the robot: that is the problem of this course. In this lesson you set up the bench, run the ready-made Unitree G1 gait policy in the "sim" and in a "simulated real" with hidden parameters, and find out that no single difference knocks it down; the sum of them does.

Start the lesson

In this lesson you will

  1. 1The five sources of the gap in a humanoid: actuator, latency, friction, mass, and contact
  2. 2The ready-made G1 gait policy (unitree_rl_lab) running in MuJoCo
  3. 3Sim × "simulated real": 4.7 m walked versus a fall in 2.3 s
  4. 4Change one parameter at a time to find the culprit

Goal: measure the gap by running the same policy in "sim" and "simulated real", and find that no single parameter brings it down.

02 · The policy and the two worlds

What runs in this course's practice sessions. Click each step.

1. The policy

Unitree publishes in unitree_rl_lab a G1 29-DoF walking policy already trained in Isaac Lab and exported to ONNX, with the deployment file deploy.yaml (joint order, kp and kd, default pose, scales). Apache-2.0 license.

It takes 480 numbers (5 timesteps of angular velocity, projected gravity, command, joints, and last action) and returns 29 position targets at 50 Hz.

2. The sim

The MuJoCo Menagerie G1 (the same one from course 0) with the policy's PD inside MuJoCo: a position actuator with the kp and kd from deploy.yaml.

Running a policy trained in Isaac Lab inside MuJoCo already means crossing from one physics engine to another.

3. The "simulated real"

You don't have a G1. The course's "real robot" is the same MuJoCo with four hidden parameters in kit/mundos/real.json. Don't open the file before lesson 3: there you discover one of them through system identification.

It's a bench test, not the robot: what it teaches is the method, not the number.

4. One at a time

--so kp makes the "real" differ only in kp. Running each parameter alone, you see that none of them knocks the policy down, but kp alone already makes it walk 50% faster than commanded.

The gap is rarely a single cause: it's the sum of small differences.

03 · Set up the bench (reuses the one from course 0)

If you did course 0, the venv and the Menagerie are already in ~/fth: this block only adds onnxruntime, the G1 in the sparse-checkout, and the unitree_rl_lab policy folder, pinned to the tested commit.

Terminal · prepare ~/fth
F=${FTH:-$HOME/fth}; mkdir -p $F && cd $F
[ -d .venv ] || python3.12 -m venv .venv
. .venv/bin/activate && pip install -q mujoco==3.16.0 numpy onnxruntime==1.31.0 pyyaml
[ -d sim2real ] || git clone -q --depth 1 https://github.com/inematds/formacao-fth-sim2real-v72 sim2real
[ -d mujoco_menagerie ] || git clone -q --filter=blob:none --sparse https://github.com/google-deepmind/mujoco_menagerie
git -C mujoco_menagerie sparse-checkout add unitree_g1 && git -C mujoco_menagerie checkout -q 62ab00f
[ -d unitree_rl_lab ] || git clone -q --filter=blob:none --sparse https://github.com/unitreerobotics/unitree_rl_lab
git -C unitree_rl_lab sparse-checkout set deploy/robots/g1_29dof/config/policy/velocity
git -C unitree_rl_lab checkout -q 4960b84 && git -C unitree_rl_lab log -1 --format='unitree_rl_lab %h (%ad)' --date=short
python3 -c "import mujoco, onnxruntime; print('mujoco', mujoco.__version__, '· onnxruntime', onnxruntime.__version__)"

04 · The same policy in both worlds

dois_mundos.py runs 10 s walking at 0.5 m/s in each world. Fall = pelvis below 0.5 m. Exits with 1 if any world fell.

Terminal · sim × simulated real
F=${FTH:-$HOME/fth}; cd $F/sim2real && . $F/.venv/bin/activate
python3 kit/dois_mundos.py; echo "saída: $?"
Terminal · one parameter at a time
F=${FTH:-$HOME/fth}; cd $F/sim2real && . $F/.venv/bin/activate
for p in atrito massa kp atraso_ms; do python3 kit/dois_mundos.py --so $p | tail -1; done
Example from the repository
política: unitree_rl_lab G1 29 GDL velocity v0 (ONNX, 480 entradas) · comando 0.50 m/s · 10 s
sim                          queda: não · andou 4.7 m em 10 s (vel. 0.47 m/s; pedida 0.50)
real simulado                queda: sim em t = 2.3 s (andou 1.9 m)
saída: 1

In the sim, 4.7 m in 10 s (0.47 m/s for 0.50 commanded). In the "simulated real," a fall at 2.3 s.

real simulado (só atrito)    queda: não · andou 4.7 m em 10 s (vel. 0.47 m/s; pedida 0.50)
real simulado (só massa)     queda: não · andou 4.6 m em 10 s (vel. 0.46 m/s; pedida 0.50)
real simulado (só kp)        queda: não · andou 7.5 m em 10 s (vel. 0.75 m/s; pedida 0.50)
real simulado (só atraso_ms) queda: não · andou 4.6 m em 10 s (vel. 0.46 m/s; pedida 0.50)

None alone knocks it down. kp alone makes the robot walk at 0.75 m/s: the softer PD lets the legs lag behind, and the policy compensates by pushing harder.
