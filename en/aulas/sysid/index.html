Lesson 3 · 17 min

System identification: measure to model

Randomizing covers what you don't know; identifying shrinks what you don't know. In this lesson you hang the "simulated real" robot on the gantry, make the leg swing in a frequency sweep, record the encoders, and use MuJoCo's own system identification toolbox to find the kp and kd the motor really delivers.

Start the lesson

In this lesson you will

  1. 1The bench test: robot hanging, leg in a sweep from 0.5 to 3 Hz
  2. 2The mujoco.sysid toolbox (MuJoCo 3.5+): Parameter, ModelSequences, optimize
  3. 3Model error dropping from 8.16° to under 4° in the positions
  4. 4Why identifying only kp goes wrong when something is missing from the model

Goal: identify the actuator's kp and kd in a bench test with the mujoco.sysid toolbox and check them against the hidden value.

01 · From the test to the parameter

Click each block.

Click each block in the diagram to see what it does.

Each test identifies what it excites. A leg in the air says nothing about foot friction.

02 · What the toolbox does for you

mujoco.sysid arrived in MuJoCo 3.5.0 (02/12/2026); here, 3.16.0 with the [sysid] extra. Tap each step.

1. Parameter

Each parameter has a nominal value, a range, and a function that writes the value into the MjSpec (the editable model). In the kit: kp and kd scale the gains from deploy.yaml on the four tested joints.

2. ModelSequences

Joins the spec, the initial state, the command (TimeSeries.from_control_names), and the measured sensors (TimeSeries.from_names).

Real trap: the model's sensors must be exactly the ones in the log. The Menagerie G1 comes with an IMU; the bench test removes it.

3. optimize

Recompiles the model on each attempt, runs the rollout, and minimizes the difference. On CPU, a few seconds to a minute for two parameters.

4. Reveal

On a real robot there is no hidden value to check against. Here there is: --revelar opens real.json and tells you whether you landed within ±10 %.

The honest check on the robot is another test, one the fit never saw.

03 · Install the toolbox and collect the test

The [sysid] extra brings scipy, matplotlib, and plotly. coletar.py records the test of the hanging "real robot".

Terminal · mujoco[sysid]
F=${FTH:-$HOME/fth}; cd $F && . .venv/bin/activate
pip install -q "mujoco[sysid]==3.16.0"
python3 -c "from mujoco import sysid; print('mujoco.sysid ok:', sysid.optimize.__name__, sysid.Parameter.__name__)"
Terminal · bench test
F=${FTH:-$HOME/fth}; cd $F/sim2real && . $F/.venv/bin/activate
python3 kit/coletar.py --saida $F/log.npz

04 · Identify kp and kd

Starts from the nominal model (kp = kd = 1.0 × the one in deploy.yaml) and adjusts both.

Terminal · sysid
F=${FTH:-$HOME/fth}; cd $F/sim2real && . $F/.venv/bin/activate
python3 kit/sysid.py $F/log.npz --revelar; echo "saída: $?"
Terminal · kp only (the common mistake)
F=${FTH:-$HOME/fth}; cd $F/sim2real && . $F/.venv/bin/activate
python3 kit/sysid.py $F/log.npz --parametros kp --revelar | tail -4; echo "saída: ${PIPESTATUS[0]}"
Terminal · the same test in the "sim" world (E3)
F=${FTH:-$HOME/fth}; cd $F/sim2real && . $F/.venv/bin/activate
python3 kit/coletar.py --mundo sim --saida $F/log-sim.npz | tail -1
python3 kit/sysid.py $F/log-sim.npz | tail -4
Example from the repository
log: ~/fth/log.npz · 1999 amostras · sinais: 8 (posição e velocidade de 4 juntas)
resíduo, modelo nominal:       0.034
resíduo, modelo identificado:  0.014
erro das posições na bancada, modelo nominal:       8.16° (RMS)
erro das posições na bancada, modelo identificado:  3.14° (RMS)
kp         nominal   1.00 → identificado   0.57
kd         nominal   1.00 → identificado   1.08
kp         escondido   0.60 · dentro de ±10 %: sim
kd         escondido   1.00 · dentro de ±10 %: sim
saída: 0

kp comes back near 0.6 (the motor delivers 60% of the commanded gain) and kd stays near 1.0, because the "real" robot did not touch kd. The position error drops to less than half.

erro das posições na bancada, modelo nominal:       8.16° (RMS)
erro das posições na bancada, modelo identificado:  3.55° (RMS)
kp         nominal   1.00 → identificado   0.52
kp         escondido   0.60 · dentro de ±10 %: não
saída: 1

With a single parameter, the optimizer dumps everything the model doesn't explain onto kp, including the 20 ms latency that lesson 4 measures. A parameter missing from the model leaks into the others: give the fit the degrees of freedom the test excites.

gravado: ~/fth/log-sim.npz
erro das posições na bancada, modelo nominal:       0.11° (RMS)
erro das posições na bancada, modelo identificado:  0.11° (RMS)
kp         nominal   1.00 → identificado   1.00
kd         nominal   1.00 → identificado   1.00

In the world with no hidden difference, the fit has nothing to correct: kp and kd stay at 1.00, and the error that remains, 0.11°, is encoder noise (0.002 rad).
